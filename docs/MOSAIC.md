# MOSAIC 最小实现

本实现验证 POI 任务协调、能力分工、执行反馈和人工干预。机器人运行在同一个 Gazebo Ionic 世界内，保留项目原车的质量、惯量、关节和轮驱动，运行时接触与轮距适配见下文，不需要训练多智能体策略。

默认使用 [`worlds/moon.sdf`](../worlds/moon.sdf) 的原始地形和岩石几何、月球重力、光照和 0.025 秒物理步长。MOSAIC 的 `scene_objects_static: true` 将岩石放在对应地表高度并固定为地质目标，避免源场景微小自由刚体在任务期间滚落十几米；车辆不采用这一固定设置。设为 false 可保留源场景岩石的原始位姿／动态属性，但当前任务流程不保证跟踪移动目标。运行时使用两辆 EXPLORER R2，分别作为 Scout 和 Scientist，复用 `moon.sdf` 引用的原始 Fuel 模型及其差速驱动插件；没有用平面或方块替代地形与岩石。源文件保持不变，生成的场景保存在每次运行的 `runtime_scene.sdf`。平地检查场景仅保留在 `configs/mosaic/flat_regression.yaml`，用于物理与故障回归。

## 论文的可视化与本实现

[MOSAIC 论文 Fig. 3 和第 4 节](https://arxiv.org/html/2601.23038v3) 展示的是一个操作系统：RViz 共享地图显示机器人、路径和交互式 POI；任务操作员查看机器人状态、相机、行为树并进行遥控；科学工作站查看测量结果、调整测量位姿。POI 的外观区分待执行、分配中和已解决任务。只观看机器人移动，无法看清这一工作流。

当前最小版提供两个窗口：

- **Gazebo 3D**：项目原始月面与岩石、两辆 EXPLORER R2 实体车，分别标注 Scout／Scientist，以及不参与碰撞的路径线和 POI 标记。相机初始视角覆盖任务区域；GUI 不加载会干扰任务时钟的暂停／重置控件。
- **MOSAIC Lunar Mission Control**：同源地形图、机器人位置／朝向、历史轨迹和剩余规划路径，POI 列表与状态、任务执行阶段、指派／停用、遥控，以及模拟科学结果和事件。

面板是轻量桌面程序，不是 RViz。执行视图显示当前简化状态机，不冒充完整行为树。相机尚未接入；结果页明确标记模拟测量。界面从模块输出的 `mission_state.json` 读取状态，通过命令适配器发出操作，不直接修改任务存储或查询仿真真值。

## 启动

先按项目 README 准备 Python 环境、原月面资产，以及 EXPLORER R2 的原始模型。模型默认由项目资产准备工具缓存到 `assets/cache/fuel`；旧平地回归另用 `assets/models` 中的改装车辆。构建包含 `mosaic-worker` 的导航镜像：

```bash
docker build --network host -f Dockerfile.navigation \
  --build-arg PROJECT_IMAGE=space_robotics_gz_envs:latest \
  -t space-robotics-rl:ionic .
```

如果没有本地基础镜像，可以省略 `PROJECT_IMAGE` 参数，使用 Dockerfile 的默认镜像。`tools/navigation/setup.bash` 也包含多车 worker 构建。

打开原始月面和任务面板：

```bash
.venv/bin/python -m space_robotics_nav.mosaic.run \
  --gui --output logs/mosaic/r2_science_demo01
```

无界面运行 360 秒仿真：

```bash
.venv/bin/python -m space_robotics_nav.mosaic.run \
  --seconds 360 --output logs/mosaic/continuous_headless01
```

`--control` 只打开任务面板，`--gui --no-control` 只打开 3D 窗口。窗口模式自动按实时节奏推进；命令行模式可用 `--realtime` 留出人工操作时间。GUI 需要桌面 DISPLAY、X11 授权及图形驱动；`--software` 可尝试软件渲染。任务面板需要 Python 的 Tk 支持，例如系统包 `python3-tk`。每次使用新输出目录，已有记录不会覆盖。

当前作业流程：

1. **探索 POI**：Scout 导航至指定位置，接受任意到达朝向；停车后分析 `exploration_seconds`（默认 10 秒）。期间线速度和角速度指令都为零，按全向感知假设工作，不进行旋转扫描。运动、侧滑或明显漂移会重新累计停稳分析时间。
2. **批量发现**：分析结束时从检测适配器读取结果，一次可登记零个、一个或多个候选。按对象 ID 去重，记录发现车辆、来源探索点和接近位置。已登记对象再次出现只更新观测记录，不重复生成候选任务；结果分别保存新候选 `candidates` 与本次看到的 `observed_objects`。途中不调用这一模拟探索检测流程；检测适配器只在进入范围后按当前对象位置和观察者位置计算接近站位，不在启动时为全部场景对象做长距离路径规划。后续真实检测器可通过适配器缓存分析结果。
3. **选择下一项**：探索任务完成后，Scout 在全部可用探索 POI、候选 POI 中评分选择。新候选不会抢占当前探索或确认任务；探索队列不足时，任务源自动生成新的探索点，没有新候选也继续探索。
4. **抵近确认**：候选配置 `confirmation_radius`（默认月面为 3 m）。只需在安全可通行的位置进入该范围并停稳，不必抵达某个精确停车坐标，也不要求最终朝向。确认适配器显式返回 `confirmed_measurement: true/false`；当前模拟适配器返回 true，测试另外覆盖 false 和缺失结果。
5. **科学任务**：确认成功后，同一个 POI 自动转成 `rock_measurement`、状态 `available`，保留 `confirmation_result`，等待 Scientist 选择；不需要人工 Approve。科学车确认自己的测量距离限制并规划停车站位，只有到站且实际目标距离满足限制时才允许调用仪器。找不到站位则保留 POI 为 `needs_help`，明确记录 `measurement_station_unreachable`，不生成测量结果，也不阻止侦察车继续探索。确认否定则标为 `rejected`，不分配科学车。
6. **独立继续作业**：Scout 完成确认即释放当前任务，继续选择探索或候选，科学车独立选择测量任务。科学车认领任务后立即向测量站位导航，不再等 Scout 先腾空才出发。导航局部地图持续包含队友占用，途中可绕行、减速，接近被占用站位时才按实际局部路径停车等待，并在路径恢复后继续。Scout 有任务就继续执行，空闲且挡住站位时才执行临时让行，刚腾出足够空间便停车，不固定返回出生点。让行期间出现新侦察任务可立即转去执行。

默认演示配置初始只有两个探索点 `(9, 0)`、`(14, 5)`，没有预置地面测量或岩石测量 POI；科学车先等待侦察发现与抵近确认。`lunar_rock0`、`lunar_rock6` 是原场景岩石簇中的两个对象，处于 14 m 模拟全向检测范围时可由同一次分析登记。它们位置接近，地图标记可能相邻；右侧对象 ID 和任务记录用于区分。默认偏好为确认 130、探索 110，再扣除路径长度和失败惩罚，因此后续任务由当前可达性和效用决定，不写死任务序列。可在配置 `pois` 中添加更多探索点，也可在面板运行时添加。

默认 `exploration.enabled: true`：`LayoutExploration` 使用当前地图生成间距 6 m 的调查站位，按每辆健康自主侦察车 2 个的总队列目标补充可用／执行中探索 POI（2 辆侦察车时共 4 个）。它过滤不满足车体足迹和余量的位置、已安排／调查过的邻近位置、过近的队友占用，并检查路径可达性。自动生成的探索任务不绑定执行者，不获得人工指派的优先级加分；人工 **Assign** 才使用该加分。初始两个探索点仅作为种子，完成它们不会自动结束任务。任务源状态分别为 `active`、`temporarily_unreachable`、`exhausted` 等，面板单独显示；只有当前地图的可调查站位用尽且所有 POI 已解决，才报告整体完成。时间预算用尽是另一种结束原因。

这是已知布局上的调查点采样，不是实时 SLAM 或真实传感器覆盖率估计。后续可替换 `ExplorationProvider.propose/snapshot` 为基于在线地图的 frontier 生成器。关闭 `exploration.enabled` 可运行固定任务表；旧平地回归采用这种有限任务模式。

旧 `--auto-approve` 参数仍兼容，但不再改变抵近确认流程。默认预算是落地初始化之后的 360 秒仿真时间，`--seconds` 可修改。无界面模式完成全部 POI 且探索任务源已结束才退出；窗口模式继续运行以便查看结果或新增任务，直到关闭面板或预算耗尽。完成退出码为 0，中断／预算耗尽为 2；它们不表示未知环境已探索完毕。检测和科学结果仍为模拟，不执行真实取样或光谱测量。

## 原始生成器随机月面与四车测试

随机场景使用项目 `scripts/procgen_assets.bash` 中相同的 `srb_assets` / Blender `LunarTerrain` 几何节点和 `LunarSurface` 材质。此前手写的平滑高度场生成方式已替换。Gazebo 直接加载生成器导出的原始 GLB（包括细节几何、UV、PBR 纹理及碰撞网格），不会将导航栅格重新导出成低精度地形。

当前测试编队为 **2 辆侦察车 + 2 辆测量车**，均为 EXPLORER R2，具有独立名称、控制话题、颜色和角色能力。默认新地图为 **80×80 m**，保留原月面的几何密度 `density=0.08`、高度参数 `4 m`、月球重力、光照和物理步长。纹理从原 40 m 地图的 4096 提升为 8192，保持相同的每米纹素密度；这不是放大旧地图或拼接重复地块。地形中的陨石坑、坡面和嵌入式碎石均来自原生成器，额外的科学目标使用原项目岩石模型与材质，保持原尺度。

已生成的四车场景可以直接启动，无需再次烘焙：

```bash
.venv/bin/python -m space_robotics_nav.mosaic.run \
  --config assets/generated/mosaic_lunar80_uniform_seed17_2s2m/mission.yaml \
  --gui --seconds 1800 --output "logs/mosaic/lunar80_uniform_$(date +%Y%m%d_%H%M%S)"
```

[新旧地图对比](../logs/mosaic/sparse_preview/comparison.png)与[新地形原生烘焙预览](../assets/generated/mosaic_lunar80_sparse_seed17_2s2m/terrain_asset/thumbnails/0.png)。按 0.9 m 足迹计算，可规划区域由约 45.0% 增至 72.4%，最大连通区域由 38.9% 增至 72.2%；阈值和采样精度相同。原高密度场景的 [Gazebo 实际渲染预览](../logs/mosaic/lunar80_render03/near.png)仍保留，静态图不替代动力学验证。

生成新场景需要项目原始 Docker 镜像（包含 Blender 4.3 和 `srb_assets`）及 NVIDIA 容器 GPU 支持。输出目录必须为空，生成日志保存在 `procgen/blender.log`，复杂网格及纹理烘焙需要等待：

```bash
.venv/bin/python -m space_robotics_nav.mosaic.generate \
  --output assets/generated/mosaic_lunar80_new \
  --seed 18 --size 80 --scouts 2 --scientists 2 --rocks 16 \
  --rock-density-factor 0.2 --pebble-spacing 2

.venv/bin/python -m space_robotics_nav.mosaic.run \
  --config assets/generated/mosaic_lunar80_new/mission.yaml \
  --gui --seconds 900 --output logs/mosaic/lunar80_new_run01
```

`--procgen-image` 可指定包含原生成器的镜像，默认 `space_robotics_gz_envs:latest`。`--terrain-model` 可以复用已生成的同尺寸原始 `model.sdf`，场景会复制其资源并校验边界，不改变原始模型。`--size` 为边长（米），`--resolution` 是导航地图采样间距（默认 0.25 m），不影响 Gazebo 地形精度；`--texture-resolution` 可以显式指定烘焙纹理大小。更大的场景需要相应的生成时间、显存与运行性能验证。

当前默认新生成场景采用 `--rock-density-factor 0.2`：内嵌岩石散布节点的 `Density Max` 从 0.5 调为 0.1，额外科学目标默认 16 个。原 `density=0.08` 控制几何细度，保持不变；地形噪声、陨石坑节点、岩石形状和 8K 材质仍由原生成器生成。配置脚本调整散布并附加低矮碎石层，原上游脚本文件不修改，参数和脚本哈希写入 `procgen/generation.json`。设为 1 可保留原散布密度。参数仅作用于新烘焙地形，`--terrain-model` 复用的 GLB 不会被重新散布。旧高密度场景 `mosaic_lunar80_seed17_2s2m` 保留用于回归。

小碎石采用独立的 XY 分层采样，不继承原散布节点造成边角空白的地形遮罩。默认 `--pebble-spacing 2`：80 m 地图划为 40×40 格，每格一块，XY 位置在格内随机扰动，再射线贴合真实地表并按法线倾斜。原生 Blender 几何检查确认 1600 格全部覆盖，每个 10×10 m 区域都有 25 块，包括四个角落；[实际几何分布图](../logs/mosaic/uniform_probe80/coverage.png)与[检查结果](../logs/mosaic/uniform_probe80/coverage.json)可核对。随机种子相同会复现布局，更换种子会改变位置。

当前新场景为 `mosaic_lunar80_uniform_seed17_2s2m`：[Gazebo 角落实景](../logs/mosaic/uniform_render/corner.png)、[原生 Blender 全景](../assets/generated/mosaic_lunar80_uniform_seed17_2s2m/procgen/lunar_surface17/thumbnails/0.png)、[加入碎石前后的导航地图](../logs/mosaic/uniform_preview/comparison.png)。可规划面积从 72.38% 变为 72.30%，最大连通区域从 72.21% 变为 72.12%；原地形未降低、未平整，增加的是贴地碎石。角落实景使用独立冻结的相机审查世界，任务运动另由真实物理运行验证。

碎石使用原生 `LunarRock` 形状，宽约 12–30 cm，总高度 3–7 cm，底部埋入 15%，露出高度约 2.6–6 cm（沿当地法线）。碎石合并进同一地形网格，一起烘焙原材质，保留真实碰撞；不作为 1600 个独立物体或科学目标。导航仍按真实高程与车辆越障阈值分类，不把这些低矮凸起一律标成禁行障碍。`--pebble-spacing` 控制均匀层疏密（允许 1 m 至半个地图边长），0 可关闭，与较大岩石的散布倍数独立。

当前稀疏场景复用已完成的烘焙资产装配，来源记录在 `scene_manifest.json` 的 `terrain_provenance`；导出的 GLB 与原烘焙产物逐字节一致，包含约 202 万三角面和三张 8192×8192 PBR 图像。

四车随机场景允许原生轮驱动倒车，并分散布置出生位置。科学车优先选择靠近自身、避开队友且满足测量距离的站位；局部堵塞时可以在不释放任务令牌的情况下换站位。每辆科学车独立提出站位，只有中标车辆的方案写入共享任务，避免互相覆盖。

放行碎石后可通行区域更大，A* 先检查起终点是否属于同一可通行区域，避免对每个不可达站位反复搜索整片地形。站位候选先按真实足迹所在的可达区域筛选，再计算路径；保留原有足迹、跟踪余量回退和禁止穿越障碍角点的约束。

规划栅格的膨胀余量与真实车体碰撞检查分开：车辆实际停在膨胀余量带、但完整圆形足迹与占用格仍有至少 5 cm 间隙时，可通过最长 1 m、逐段检查完整足迹的连接重新接入规划区域。局部速度预测同样按连续车体中心和占用格面积检查，仍包含队友与地图边界；不清除障碍格，也不允许从真实重叠位置直接穿出。控制器跳过路径点前验证连接，队友挡住后续连接时会触发局部重规划，避免原地等待或反复前后挪动。

偏置转动中心可能使最短方向的原地转向暂时靠近障碍。局部脱困会预测低速直行、转动和允许的倒车动作，选择能安全增大间隙的动作，再从实际新位置重新规划。近处站位实际被占用时仍停车等待和重规划，不为清除纯余量带而穿过队友。

大地图上的导航时限按首次有效路径长度计算：`max(180 s, 1.6 × 路长 / 车辆最大速度 + 60 s)`。0.25 m/s 的车辆行驶 45 m 已需 180 秒，原固定时限会让正常跨地图任务过早失败。预算只在首次有效路径确定时计算，地图更新和重新规划不刷新截止时间；任务总时限至少覆盖该预算再加 180 秒，并始终相对最初认领时间计算。局部持续阻塞 30 秒和全局无路等待 45 秒仍分别失败，测量距离、静止要求及碰撞检查保持有效。

本场景使用的模拟岩石仪器按距离与静止条件取样，不要求车身最终对准（`instrument_requires_heading: false`）；仍需到达规划站位，且实际目标距离必须不超过 3.5 m、停车稳定至少 2 秒。方向性仪器可设为 `true`，或由替换的仪器适配器提供 `requires_heading`。这项简化不替代真实载荷的朝向与测量能力验证。原双车回归保留原朝向要求。

初始任务表只有探索 POI。场景岩石只是模拟检测器的环境对象，不会提前登记为科学任务。侦察车在探索点停车分析 10 秒，可登记多个候选；候选经侦察车抵近确认后才进入测量车任务队列。探索任务队列随侦察车数量补充，共享 POI 令牌避免同一任务重复执行。

`scene_manifest.json` 记录原生成器来源、模型与场景信息；`heights.npy` 由原始碰撞网格射线采样；`terrain_heights_fine.npy` 保存不超过 0.1 m 间距的原始高程证据。导航依据车辆尺度的持续坡度和局部高差生成 `terrain_blocked.npy`，不再把碎石的尖锐边缘一律当作陡坡。旧场景启动时会从原碰撞网格补建细高程缓存，随后按当前参数重新分类，无需重新生成 Blender 地形。

目前四辆 R2 共用 `map.max_step_height: 0.12`（米）的保守越障阈值。独立岩石按真实位姿下高出当地地面的高度分类；低矮岩石保留在仿真、检测器和 POI 管理中，但不占用禁行栅格。地形中的碎石结合 `ground_smoothing: 0.20`、`roughness_window: 0.60` 区分短小凸起与持续坡度；大岩石、陡坡、未知区域及其他机器人仍限制通行。原始地形、岩石碰撞和车体足迹保持物理有效，面板障碍层与导航使用同一分类结果。

接触反馈区分轮胎与车身：轮胎接触已判定可通行的低岩石不会触发碰撞故障；车身接触（包括擦碰地形）、轮胎接触不可通行的独立障碍物或其他车辆仍会触发故障。普通轮胎与地形接触继续按正常行驶处理，地形禁行由高程分类与导航约束。旧 worker 无此细分字段时保留保守碰撞判断，需使用已重建的运行镜像。原生 R2 在独立平地测试中分别越过 5、10、15、20 cm 台阶；另有 10 cm 实体障碍的完整导航与健康状态回归。该证据支持当前 12 cm 起始设置，不代表任意坡面、速度和岩石形状都能越过 20 cm。后续更换车型时应按实际越障能力调整参数。机器人仍通过原生轮子和接触物理运动，定位暂用真值，检测与仪器暂为模拟，后续模块接口保持独立。

原先 `.cache/mosaic/scenarios/random100_seed7` 和 `random160_seed19` 是旧简化地形产物，不作为本轮环境质量与四车验证依据。原 40 m 双车回归配置仍可用 `configs/mosaic/demo.yaml` 启动。

## 面板操作

- 地图中点击机器人或 POI 进行选择；右侧显示对应任务、执行阶段和结果。右键拖动平移，滚轮缩放，**Fit** 复位。
- 勾选 **Add POI**，选择任务类型，点击地图并输入朝向，可新建导航、探索或地面测量任务。
- POI 按钮提供 **Assign / Deactivate**。**Assign** 指派给当前选中机器人，能力与任务状态仍由任务层校验。颜色图例区分可用、执行中、完成和需要帮助。候选是否转成科学任务由抵近确认结果决定。
- 机器人按钮提供 **Pause / Resume AUTO / Disable**。按住方向按钮遥控，松开停车；恢复自主执行需要 **Resume AUTO**。遥控租期会自动续租，失去续租后停车。
- 执行页显示当前任务与阶段、分析剩余时间、局部地图来源和重新规划计数；选中任务还会显示最近一次失败原因、时间及相关科学车当前到目标的距离；选中候选会画出确认范围，选中 POI 会显示执行者、等待原因及接近点。科学页显示探索得到的候选列表、抵近确认记录或科学测量结果，模拟数据带 `simulated` 标记；事件页记录发现、认领、确认和操作拒绝原因。

已结束的记录可重新打开查看，不能继续控制：

```bash
.venv/bin/python -m space_robotics_nav.mosaic.control logs/mosaic/moon_headless01
```

## 命令适配器

`--commands /tmp/mosaic_commands_run01.jsonl` 可接入追加式 JSONL 命令文件；每个完整行是一条命令，半行等待后续数据。为新运行使用新文件，避免重放。面板使用输出目录的 `control_commands.jsonl`，两者经过相同任务命令接口。

| 操作 | JSON 示例 |
| --- | --- |
| 暂停并释放任务 | `{"op":"pause","robot":"explorer_r2"}` |
| 恢复自主任务选择 | `{"op":"resume","robot":"explorer_r2"}` |
| 标记车辆失效并释放任务 | `{"op":"disable","robot":"explorer_r2_science"}` |
| 遥控接管 | `{"op":"teleop","robot":"explorer_r2","velocity":[0.1,0],"seconds":1}` |
| 指派可用任务 | `{"op":"assign","robot":"explorer_r2","poi":"explore_lunar_site"}` |
| 新增导航任务 | `{"op":"add_poi","id":"move_01","kind":"move","pose":[10,-8,0]}` |
| 停用 POI 并取消当前执行 | `{"op":"remove_poi","poi":"explore_lunar_site"}` |
| 注入定位失效／恢复 | `{"op":"localization_valid","robot":"explorer_r2_science","valid":false}` |
| 注入地图更新 | `{"op":"map_block","bounds":[9,-12,10,-11],"blocked":true}` |
| 结束本次运行 | `{"op":"stop"}` |

遥控速度单位为 m/s、rad/s，单次租期为 `(0,5]` 秒；遥控同样检查定位、局部地图和障碍占用。`map_block` 只更新地图证据，不会在 Gazebo 中生成物体。地图点击也不保证所选点可达；导航模块会进行可通行性检查。

`--script` 可执行包含 `at` 字段的 YAML 命令列表，时间相对初始化落地完成。原平地故障回归示例：

```bash
.venv/bin/python -m space_robotics_nav.mosaic.run \
  --config configs/mosaic/flat_regression.yaml \
  --script configs/mosaic/faults.yaml \
  --output logs/mosaic/fault_run01
```

## 模块边界

接口在 `space_robotics_nav/mosaic/contracts.py`，不依赖 ROS 或 Gazebo 消息。`Mission` 接收模块对象，运行器负责创建适配器和转发数据。

| 模块 | 当前实现 | 后续接入方式 |
| --- | --- | --- |
| `LocalizationProvider` | Gazebo 车体世界位姿，世界到 `map` 为单位变换 | 发布带时间戳、有效状态、速度、可选协方差的实时定位结果 |
| `MapProvider` | `ProjectMap` 从原始地形碰撞网格提取高程、坡度与粗糙度，再投影实际岩石碰撞边界；接收仿真中岩石位姿变化 | 用在线建图发布地图版本／增量，未知区域标为阻塞 |
| `LocalMapProvider` | 已知地图的 5 m 裁剪，叠加队友实时占用 | 替换为传感器生成的局部地图，保留时间戳和坐标系 |
| `ExplorationProvider` | 已知地图上的安全站位采样，补充探索任务，跟踪任务源状态 | 用实时地图的 frontier／信息增益策略产生新调查点 |
| `DetectionProvider` | 原场景对象位置的范围门控；没有图像识别、遮挡或噪声模型 | 发布带对象 ID、目标位置、接近位姿、确认范围和置信度的批量检测结果 |
| `GlobalPlanner` | 膨胀可通行栅格上的 A* | 接入布局、地形或在线地图规划器 |
| `LocalController` / `Navigator` | 路径跟踪、速度候选检查、局部占用重规划、末端对齐 | 替换局部规划器、感知导航策略或整个异步导航动作 |
| `Instrument` | 水平速度低于 0.03 m/s、角速度低于 0.04 rad/s，且 2 秒内漂移不超过 0.05 m 后返回 `simulated` 结果 | 实现异步 `start/tick/cancel`；候选确认须显式返回布尔 `confirmed_measurement`，科学任务返回真实测量结果 |
| `HealthProvider` | Gazebo 接触反馈与翻倒检查 | 接入底盘、碰撞、设备故障状态 |

原始地图提取复用本项目的资产解析、碰撞几何和地形射线工具；面板栅格与导航使用相同地图对象。出生高度和姿态由当地地形计算，随后在 Gazebo 中落地。全局规划使用真实地形的二维可通行性栅格，当前并不是完整三维地形规划器；地图分辨率、坡度和高程残差阈值位于默认配置。

岩石的 `target` 是实际对象位置；`approach`／`navigation_station` 是导航停车站位，两者分别显示。Scout 的确认范围为 3 m，并在车体足迹之外预留 0.6 m 接近规划余量，可以进入范围后直接停稳，不要求精确停车点或最终朝向。

Scientist 的 `measurement_max_distance` 默认 **3.5 m**，是测量允许的最大车体中心到目标距离，不能为了找可通行位置而自动放宽。站位在候选确认后，根据科学车当前定位、地图、原生车体足迹和路径可达性规划；仪器启动前和执行期间再检查实际站位与目标距离。记录包括 `target_distance`、`maximum_distance`、`station_error`。站位中心必须满足 `距离 + position_tolerance + 0.05 m <= measurement_max_distance`，为完整到点容差和停稳漂移预留空间。默认科学站位因此位于目标 3.0 m 内，而非贴着 3.5 m 边界停车。实际测量距离仍逐次检查；超限时取消仪器动作并返回导航纠偏，不立即消耗任务失败重试。

科学车当前与侦察车使用相同的 EXPLORER R2 原始模型、0.9 m 足迹和转向／停靠参数，仍只具备移动、地面测量、岩石测量能力，不参与探索和候选确认。此前 NASA Perseverance 的 2.75 m 保守足迹导致这组岩石在 3.5 m 内无可达站位；更换模型后按新足迹重新规划，测量距离限制仍为 3.5 m。默认 `measurement_clearance: 0.6` 给科学站位规划增加 0.6 m 余量，科学车 `tracking_margin` 同为 0.6 m，让站位可达性检查与实际路径规划使用一致的余量。车体足迹仍为 0.9 m，不靠缩小真实车体避障范围来寻找站位。任何无法抵近的任务仍保留 `needs_help` 并显示原因。

先前版本把约 6.7 m 外的可达停车点作为科学站位，并仅凭停稳返回模拟成功；该行为已经取消。面板对不可达科学任务不再画出一个有效停车点，结果页区分“侦察确认记录”和“科学测量结果”。当前模拟适配器没有真实相机或机械臂，所以距离限制仍是显式的任务假设，不是已验证的真实仪器能力。


新增模块应在工厂注册并修改 provider 配置，或直接传入符合接口的对象。未知 provider 报错，不会静默回退到真值。替换底层模块不需要修改 POI 认领和状态机。当前尚未实现实时 SLAM、传感器融合、视觉检测、相机画面或 ROS 2 传输。

所有任务位置使用 `map` 坐标系。传感器结果需由适配器先转换；没有通用 TF 管理器。`target` 是检测／测量对象，`approach` 是机器人导航目标。定位／局部地图过期 0.6 秒或无效时停止导航；已知静态地图不按采样频率过期。队友定位失效后保留最后有效占用；失联车辆的长期运动不确定性仍需后续扩展。

## 协调与控制

默认演示配置和当前 80 m 均匀碎石配置采用 **深度 3 的多步贪心 POI 规划**，折扣为 0.8。每车按能力、任务类型偏好、路径长度和失败历史评分，逐步预测完成后的停车位置和完成时间，再从预测位置规划下一项。当前执行项也计入深度；因此最多显示“当前任务 + 两个后续意向”。探索与候选确认参与同一轮评分，不设置候选强制抢占，也不会因新任务出现而取消正在执行的正常任务。该方法逐步选择局部最优项，没有枚举所有序列或按累计序列收益反向选择第一项。

单步效用仍为 `任务偏好 − 规划路径长度 − 10 × 本车在该 POI 的非取消失败次数 + 人工指派奖励 1000`，第 d 步发布 `效用 × 0.8^d`。先按直线距离下界构造效用上界，筛去无望竞争的组合，再进行真实足迹 A* 和科学站位查询。路径长度使用当前已知地图，非导航栅格的直线连线；预计行驶时间暂用 `路径长度 / (最大速度 × 0.8)`，加探索 10 秒或仪器停稳至少 2 秒，不代表准确动力学 ETA，也未模拟电池。

同一轮规划先为所有空闲车辆分配立即可执行的任务，然后协调后续项。**当前任务严格独占，远期任务协调去重、允许让位。** 当前项通过共享管理器认领并获得令牌；后续项仍为 available、无令牌，不阻止空闲车辆立即竞争。每个发布计划集合中，一个 POI 只归属一个后续意向。重新规划时原远期归属获得 5 分的协调滞回，仅作用于远期竞争，不增加任务收益，也不阻止立即执行的车辆；明显更优的远期竞争者仍可接替。人工指派仍限制 eligible 的机器人。

规划每 2 秒刷新，任务集合、类型、认领状态、人工模式、定位有效性或地图版本变化也触发刷新；后台正在计算时只保留一个快照。意向有效期为 20 秒，暂停、失联、任务删除／转换、地图改变或任务已被认领会清除受影响的意向。计算结果返回时再检查地图版本、POI 修订、当前执行令牌和车辆起点；过期结果不能启动任务。正式执行科学任务前重新核对当前可达站位和测量范围，不沿用陈旧预测绕过安全约束。

`poi_planning.py` 只读脱离实时状态的快照，不持有检测器、仿真真值或 POI 管理器；预测不会提前发现岩石、把候选标成已确认、或为其生成虚构的科学任务。科学站位查询支持显式预测起点，不会临时修改实时定位。下一项任务实际完成后再按真实检测结果更新。工作线程不修改真实 POI，认领和执行始终由任务主线程负责。

配置示例：

```yaml
poi_planning:
  depth: 3
  discount: 0.8
  interval: 2.0
  intention_ttl: 20.0
  switch_margin: 5.0
  wall_budget: 1.0
  max_queries: 128
exploration:
  enabled: true
  queue_size: 3
```

序列搜索在线程中运行，主控制循环轮询结果，不等待整次搜索。每轮最多 128 个详细候选查询、默认 1 秒墙钟计算预算；A* 每 128 个展开点检查截止与取消信号，达到预算时发布已完成的部分计划。单次底层数组操作不能被硬中断，因此预算不是硬实时保证。缓存包含地图版本、机器人足迹、预测起点、目标修订和必要的队友占用。设置 `depth: 1` 可复用原单步调度用于对照；未配置 `poi_planning` 的历史场景保留深度 1 行为。新生成的四车场景每辆侦察车维持 3 项可用／执行中的探索任务，保证深度规划有足够已知候选；原 40 m 双车配置保留每车 2 项，队列大小与规划深度分别配置。

面板的 **POI plan** 页显示本车的有序 POI、原始／折扣效用、预计路径长度、ETA 和计划版本；执行页另显示简短序列。地图虚线连接远期意向站位，仅表示任务顺序，不是局部无碰撞轨迹。[实际运行快照的面板预览](../logs/mosaic/depth_ui_preview/panel.png)可核对。`mission_state.json`、`summary.json` 中的 `poi_planning` 保存序列和未来归属；`poi_plan_published` 事件保存规划版本、耗时和预算是否截断；遥测额外记录 `decision_wall_seconds`、`planned_sequences`、`future_owners`，可检查重复意向和控制延迟。

令牌与租期阻止重复执行及过期结果。失败冷却 10 秒，累计 3 次非人工取消失败进入 `needs_help`。只有其他机器人具备相应能力时才能接替任务。科学站位不可达会保留待处理状态，不会将它当成已测量或静默改用更远的位置。

地图更新导致路径短暂不可达时，车辆停车、保留认领并持续重新规划，面板显示等待路径；全局路径持续不可达超过 45 秒才报告失败。局部路径持续阻塞超过 30 秒报告失败。人工取消不计入失败冷却。

这是 MOSAIC 工作流的最小实现：按机器人偏好进行多步状态预测，在同一进程内协调后续意向；没有复现跨机器人分布式通信、完整行为树或多车时空轨迹规划。深度规划不能替代局部避障，也不保证任意地形和会车布局无死锁。算法依据论文第 IV-C-3 节的多步贪心与深度折扣思想，集中式当前项优先、TTL 和滞回是本项目的实现选择，不声称逐行复现论文代码。

后端一次接收所有车辆速度，统一推进世界。控制周期 0.2 秒：默认原月面对应 8 个原始物理步，平地回归对应 40 个 0.005 秒物理步。每车使用独立 `/model/<name>/cmd_vel`，切换任务不重置世界。

默认两车均为原始 EXPLORER R2：侦察车实例名 `explorer_r2`，科学车实例名 `explorer_r2_science`。任务面板标注相同车型与不同的 Scout／Scientist 角色。两车独立加载模型，保留原始质量、惯量、碰撞几何和轮子，原始缓存文件保持不变。运行时副本将轮胎的 `slip1/slip2` 设为 0，避免零轮速时仍发生持续侧滑；EXPLORER 的驱动轮距从原场景的 0.275 m 修正为与轮心布局一致的 0.726 m。每车使用独立控制话题。车辆仍通过轮速和物理接触运动，地形、重力和物理步长保留原值。模型中用于调试的传感器视锥显示关闭，传感器接口仍保留。NASA Perseverance 适配器仍保留供自定义配置使用，其模型 -Y 前向和坡面姿态转换由独立测试覆盖；默认场景不加载该车型。

默认两车均使用 0.9 m 保守圆形足迹。加载配置时检查足迹不能小于原 EXPLORER R2 碰撞几何的包围半径（约 0.87 m）。优先预留额外跟踪余量；站位规划和实际导航都可回退到满足完整真实足迹的路径，避免上次停靠位置落入额外余量带后被误判为无法出发。目标站位本身仍保留配置余量。`turn_offset` 补偿车体原点与转动中心偏移。探索和候选确认忽略到达朝向；普通移动和科学测量仍按目标朝向对齐。探索阶段只停车等待分析，不执行扫描转向。车型配置中的 `yaw_rate_damping` 提供角速度反馈阻尼，减小低重力下的转向振荡。默认两车到点位置容差 `position_tolerance` 均为 0.45 m，实际停车位置会写入结果；这不构成真实仪器测量的位姿精度验证。局部控制可减速、停车和重规划；持续阻塞／超时会报告失败。这不是完整多车时空规划器，不能保证任意会车布局无死锁。更换车型、载荷和工作关节姿态后需要重新检查足迹。

## 记录与验证

测试与实际运行结果见 [验证记录](mosaic_validation.json)。验证包括固定 10 秒停车分析、批量候选与重复观测去重、无新候选后自动产生并执行后续探索点、任务源耗尽与暂时无路的区分、测量站位和距离硬约束、无法抵近的科学任务保留，以及真实 Gazebo 下超过原有限演示结束时刻后的持续运动。旧平地场景验证可达站位内的完整确认／测量链。原始模型文件保持不变，运行时接触与轮距适配另外记录；这些结果不代表任意地形的导航成功率。

当前完整 MOSAIC 回归 **95 项通过**（包含 Gazebo 与 Tk），全项目非仿真检查 **168 项通过、16 项跳过**。新增覆盖深度状态递推、折扣效用、未来意向唯一归属、当前执行机会优先、滞回与让位、只认领首项、过期／地图变化／人工指派作废、任务不被抢占、后台计算不阻塞控制，以及不提前生成科学任务。

- `control_commands.jsonl`、`control.log`：使用任务面板时的命令与进程日志。

仿真真值通过定位／健康／已知场景适配器进入模块，并保存供评估。接入真实模块时应保留评估记录，同时切断运行模块的真值输入。
