# 原 Gazebo 中的近目标规划与停靠

目标是让现有 RL 策略负责接近目标，规划与反馈控制负责最后的完整位姿收敛。
本功能默认关闭，使用 `play`、`evaluate` 的 `--terminal-planner` 开启。
不需要重新训练模型；原机器人、控制插件、资产、物理引擎、训练／评估任务采样、奖励、
150 秒回合限制以及 `距离 < 0.18 m 且朝向误差 < 0.1 rad` 的成功条件均保留。

## 行为

1. 距离大于 2 m 时执行策略原始动作。进入范围后尝试求解；没有有效路径时继续 RL，
   不因一次未被接受的接管而插入停车动作。
2. 接近阶段枚举 Reeds–Shepp 曲线与前进／倒车的差速转动—直行—转动路径。
   根据预计执行时间、倒车代价和换向停车代价排序，检查完整路径后选取候选。
3. 接管时先减速，再通过原 `/cmd_vel` 发送闭环线速度和角速度。
   最大请求速度为 0.25 m/s、0.6 rad/s，且不超过原控制器限制。
4. 距离进入 0.6 m 后使用差速停靠；离开 0.9 m 后重新进入接近阶段。
   从实际线速度／角速度估计低速转向时的转动中心偏移，变换当前位姿和目标位姿，
   修正原机器人转向时机体参考点的侧移。朝向对齐仍以原机体参考点和原目标为准。
5. 每 2 秒重规划，每 1 秒更新局部地图；岩石位姿明显变化时提前更新。
   每个控制步还检查反馈动作和实际速度对应的短时扫掠区域。
6. 已接管后路径失效、跟踪扫掠不安全、超过 50 秒或离开 3 m 范围时，
   先发出一次停车请求，再返回 RL，等待 2 秒后重新尝试接管。
   实际碰撞仍由 Gazebo 接触力和原终止函数判定。

`--terminal-family rs` 限制接近阶段的候选族；末端差速停靠仍存在。
这不是全局搜索规划器；有限的解析连接都无效时会拒绝接管。

## 原地图与机器人尺寸

规划地图来自 `Terrain` 中的原地面碰撞网格与原岩石碰撞体，动态物体使用 Gazebo
反馈的当前位姿。局部窗口随机器人移动，覆盖退出距离、机器人半径和检查余量。
它额外提供了原 RL 5×5 m 高度扫描以外的局部几何信息，因此混合结果单独标记为
`navigation_mode=rl+terminal`，不记作策略网络本身的能力提升。

原机器人 SDF 的箱体、圆柱和网格碰撞体用于计算参考姿态的外接圆：
Moon 约 0.869 m，Mars 约 2.713 m；另外保留 0.1 m 余量和栅格离散余量。
这是保守的平面检查，不是精确的三维连续碰撞检测。轮系形变、滑移和地形影响
仍依赖实际 Gazebo 反馈与接触检测。

地图分辨率 0.1 m，路径平移采样不大于 0.05 m。地面用 0.15 m 高斯尺度平滑，
坡度上限默认为 rise/run=0.6；原地面高度与平滑面的残差上限为 0.16 m。
这些是末端模块的可配置检查参数，不是对机器人可跨越台阶高度的保证。
未知区域、过陡区域和大残差区域均拒绝通行；原岩石始终额外投影并按机器人尺寸膨胀。

特别注意，上游 `slope_limit=0.35` 是出生点采样时未归一化的 Sobel 阈值，
不能直接解释为物理坡度。这里没有修改其采样公式和参数。
可通过 `--terminal-max-slope`、`--terminal-height-residual` 调整末端检查。

## 使用和评估

```bash
# 原任务、同一 checkpoint、相同种子，分别保存纯 RL 与混合结果
uv run --frozen python -m space_robotics_nav.evaluate \
  logs/navigation/moon_v2_native_std_16env_seed42/final.pt \
  --device cuda:0 --episodes 8 --seed 30000 --num-envs 4 \
  --output logs/navigation/terminal_baseline.json

uv run --frozen python -m space_robotics_nav.evaluate \
  logs/navigation/moon_v2_native_std_16env_seed42/final.pt \
  --device cuda:0 --episodes 8 --seed 30000 --num-envs 4 --terminal-planner \
  --output logs/navigation/terminal_hybrid.json

# 在原 Gazebo GUI 中观看；控制台显示当前控制模式
uv run --frozen python -m space_robotics_nav.play \
  logs/navigation/moon_v2_native_std_16env_seed42/final.pt \
  --device cuda:0 --goals 10 --terminal-planner
```

默认确定性播放、每次启动随机生成 10 个目标。到达／超时后从当前位置继续，
碰撞／越界／翻倒后恢复出生点；`--goals 0` 持续运行，`--reset-between-goals` 改为每段独立重置。
不传 `--seed` 使用新随机运行种子；复现单个案例使用 `--seed 30002 --goals 1`。
摄像机默认跟随，`--fixed-camera` 保持固定视角；绿色目标与要求朝向随任务更新。
可通过 `--output` 保存目标、起止位置、切换原因与结果。
连续播放是单独的可视化流程；下面的性能评估仍使用原来的独立回合重置。

随机动作播放和评估均按每个回合的 `12345 + seed` 初始化动作随机数，
仍可能存在物理数值差异。查看 JSON 的严格成功率、碰撞率、最终距离／朝向误差，
以及 `terminal` 中的接管、选路、规划失败、回退和控制步数。
每个回合自动重置末端控制器，避免上一回合状态污染下一回合。

## 代码和来源

- `space_robotics_nav/planning/paths.py`：RS／差速位姿连接和转动中心变换。
- `space_robotics_nav/planning/local_map.py`：原资产外接圆、原地图检查、动态岩石更新。
- `space_robotics_nav/planning/terminal.py`：接管、减速、跟踪、停靠和失败处理。
- `evaluate.py`、`play.py`：可选接入；`train.py` 不接入规划动作。

RS 的 12 族解析公式取自 MIT 许可的
[PythonRobotics 固定提交 b5988db](https://github.com/AtsushiSakai/PythonRobotics/blob/b5988dbcbc3c1d8cdbb3f9f3f9dec75cf63defb9/PathPlanning/ReedsSheppPath/reeds_shepp_path_planning.py)，
保留作者信息和完整许可证。只提取数学公式，未引入其场景、机器人或绘图依赖；
对称变换、路径采样、数值端点校验、选路和控制接口由本项目实现。
读取原 Mars DAE 碰撞网格所需的 `pycollada==0.9.3` 已锁定在依赖中。

数值测试覆盖 RS 端点／倒车／奇异位姿、转动中心变换、完整轮廓检查、未知区域、
物理坡度、动态障碍、减速、滞回、失败回退、回合重置及带偏移和转向响应误差的闭环收敛。
Gazebo 集成测试额外验证原机器人上的短距离位姿任务；该合成任务不计入模型性能评估。

## 实测

完整逐回合数据、配对 bootstrap 区间、配置、模型和原文件 SHA-256 记录在
[验证 JSON](navigation_terminal_validation.json)。均使用同一份
`moon_v2_native_std_16env_seed42/final.pt`，确定性动作、4 个原 Gazebo 实例，
没有重新训练。原 9 m 目标、随机目标朝向和 150 s 时限均保留。

| 种子组 | 严格成功率：纯 RL → 混合 | 碰撞率：纯 RL → 混合 | 平均最终距离 | 平均总回报 |
| --- | --- | --- | --- | --- |
| 调试组 30000–30007，8 回合 | 0/8 → 2/8 | 50% → 37.5% | 3.061 → 2.487 m | 0.092 → 0.365 |
| 新组 31000–31015，16 回合 | 0/16 → 5/16（31.25%） | 25% → 25% | 1.801 → 1.247 m | 0.416 → 0.541 |

新组平均最终朝向误差从 1.858 rad 降至 1.137 rad；配对总回报增益为 0.124，
95% bootstrap 区间约为 [0.001, 0.265]。新组 8 个回合接受过接管，其中 5 个成功、
3 个仍未完成；4 次碰撞均发生在没有接受接管的回合。
剩余失败还包括地形检查拒绝接管和末端跟踪未收敛。

种子 30002 曾在纯 RL 中接近目标至 8.2 mm，却在 750 步超时后距离目标 1.397 m。
混合方案在 235 步完成，最终距离 0.150 m、朝向误差 0.041 rad、没有碰撞。
这验证了接近阶段执行 RS、末端差速控制的完整链路。

末端模块首轮交付时 **59 项测试通过**，包括原月球／火星环境与控制检查和新增的月球停靠集成测试。
另外通过 Python 编译、依赖兼容检查、格式检查、wheel 构建及许可证打包检查，
并使用实际 checkpoint 验证播放与评估的每回合随机动作流一致。
19 个原环境、训练、奖励、源算法和配置文件与当前提交保持一致。

之后增补连续播放功能，测试总数为 **69 项**；实际 GUI 的 10 目标切换记录见
[连续播放验证](navigation_playback_validation.json)。连续播放与上表的独立回合评估分别记录。

调试组参与过控制器调整，新组在参数固定后独立运行，应分开解读。
这些是单一模型的小样本结果；当前交付验证了末端模块的收益，仍需要更多训练种子和
任务验证可靠性。Mars 已验证资产读取和原控制接口，尚无 Mars 模型的端到端性能结论。
